\section{Collaborative Writing and Version History Evidence}
\label{app:collab}

The technical-report rubric requires the report to ``show evidence of
collaborative writing, not just a final PDF.'' For this project, that
evidence comes from GitHub and Git. The report \texttt{.tex} sources,
the SQL queries, the Streamlit dashboard, the Alembic migrations, and
the schema documentation all live in the same project repository, and
every commit carries author and timestamp metadata. The Git history
therefore captures the version history, the per-author edit
contributions, and the revision timeline that the rubric asks for, in
a single auditable trail.

Figure~\ref{fig:gitlog-report} reproduces a slice of the project
\texttt{git log} that spans the report, SQL, dashboard, and schema
work. The lifecycle covers the initial scaffolding through the final
submission and shows commits from all three authors: Naman Sudan,
River Roseveare-Hunt, and Ishaan Shetty.

\section{Reproducing Every Number in This Report}
\label{app:repro}
Every numeric claim in the report is reproducible from the loaded
database. The mapping is:
\begin{itemize}
  \item Row counts (Table~\ref{tab:rowcounts}): \texttt{SELECT
    COUNT(*) FROM <table>;} for each row.
  \item Query results (Section~\ref{sec:sql}): paste the
    \texttt{SELECT} from each subsection into psql.
  \item EXPLAIN ANALYZE numbers (Section~\ref{sec:explain}): run
    \texttt{advanced/naman\_explain\_index\_improvement.sql}
    against the loaded database with Alembic at head
    \texttt{742e860d116f}.
  \item Dashboard KPI defaults (Table~\ref{tab:kpi-defaults}):
    \texttt{streamlit run src/dashboard/app.py}, leave the
    sidebar at story-canon defaults, read the four
    \texttt{st.metric} cards.
  \item Saved view contents (Section~\ref{sec:view}):
    \texttt{SELECT *} \texttt{FROM v\_privilege\_escalation\_timeline
    ORDER BY timestamp;}.
\end{itemize}
